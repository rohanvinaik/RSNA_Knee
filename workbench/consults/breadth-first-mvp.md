# The lead's own reading: a breadth-first MVP, every stage runs and renders

Written **before** either second reader's answer for this round (`docs/SPINE.md`, the working loop,
step 3). The founder, 2026-10-11:

> "Recovering context is the expensive part. I can afford to spend tokens, but a fluid intelligence
> oracle is expensive to maintain… let's build wide. I can get to the refinement of the baseline
> functional pipeline when it actually EXISTS, and each step can put out a non-stupid image, even if
> it's not actually good quality."

> "build the basic hardware of the \<object> thesis, sufficient to enable us — following some direct
> guidance with domain-knowledge, fluid-intelligence oracle, PI-undergrad work — to assign meaning to
> the tooling's output as annotated/processed visual data."

**So: mechanism now, meaning later.** No stage names anatomy, admits an object, or decides that a
reading means a cortex. Every bar a stage reads is an **argument, never a constant** — the stage
runs, records what it did and on what warrant, renders it, and he assigns the meaning from the
picture.

## The one architectural claim this rests on

**Every stage must be total over a missing predecessor.** If a stage's input is absent, it returns a
named code and renders an honest empty frame — it never fails, and it never substitutes a default.
That is already the project's law (*a missing reading is silence, never a negative*; *decide or
abstain*), and it is what makes a breadth-first build possible at all: stages become independently
buildable and simultaneously wireable, because none of them depends on another being good — only on
another being *honest about being absent*.

Without this, breadth-first is impossible and the only order is depth-first. With it, the twelve
stages are a shotgun.

## What "MVP" means for each stage

The route must be the **object model's** stages before anything is built against it — `ROUTE` still
carries Figure 8's transcribed names, which `docs/SPINE.md` says are superseded. That is **task
1.4**, and it moves from "cheap and open" to *first*, because breadth-first against a superseded
table builds twelve things in the wrong shape.

| stage | the MVP record | the MVP picture |
|---|---|---|
| study | built | built |
| field (collapse) | regime key, noise law, physical frame, squint — mostly built | built |
| lenses | one ternary digit per place per acquisition, against the **series' own tercile edges**, which `RegimeKey.terciles` already computes | the three-colour digit map per acquisition |
| objects | territories + census + the contour chains of 3.8–3.12 | arcs in the colour of their warrant |
| relations | per touching pair, the constructed interstice: its divide sites, its relief, the places between — all already in the census | the interstice drawn between two territories |
| ownership | every place assigned to a territory, an interstice, background, or **unassigned**; the residual reported | the ownership map, with the residual visible |
| bundles | per object, its profile as row counts over the banks available today: the voxel's digit per acquisition, the dome link's direction, the ring | the count table, as figure 26 panel C draws it |
| predicates | the twelve, each a named decision over its subject, returning **abstained** everywhere | a twelve-row table per study, every row abstaining with its reason |
| output | twelve confidences per study in the submission's schema, all at the abstention value | the written file, validated against `sample_submission.csv` |

**The upper stages abstaining is not a failure, it is the honest baseline.** A pipeline that reaches
`output` and abstains on all twelve *exists*, proves every wire, and matches the project's own
epistemology. Every later increment then turns one abstention into an assignment **with a warrant**,
and the score moves for a reason that can be named.

## The lenses MVP, which is the one real design choice

The static middle is settled — a pair of edges at the terciles of a structurally selected
population, both edges in the 0 row — but the knee's **local structural normalisation** is the
founder's and is not given. The MVP therefore reads the terciles of the **series' own foreground**,
with no spatial correction, and says so in its record: `normalisation: none`. That is a real reading
against the image's own distribution (which is what defeats scanner scaling), it is honest about what
it does not correct for, and the normalisation refines it later without changing the stage's shape.

`digits.digit_code` still has the old shape (a witness middle plus a spread band) and takes the
low/high-edge correction first. That correction is independently settled and blocks nothing.

## The discipline, per stage, unchanged

Each MVP unit gets the full twelve-step loop: declared in OpenSpec before code; a pure decision total
over its arguments returning **named codes**, with every bar an argument; PEP 316 contracts;
two-sign intent tests calling directly; `just detective converge` with **every survivor judged**;
`just crosshair`; wired into the production route so something consumes it, with `just graph` showing
nothing dangling and `just imports` holding the layer contract; a `ComputeContract` and ledger
telemetry; a renderer that only **arranges** values the stage computed; and a run on real data
through Chapter 1's entry point.

A stage is not `built` until it renders. A renderer that has to measure is evidence against the
stage.

## What I am least sure of

- **Q1.** Is "total over a missing predecessor" sufficient to make the stages independently
  buildable, or does some pair have a real ordering dependency that abstention cannot paper over?
- **Q2.** Is an all-abstaining `predicates`/`output` pair an honest MVP, or does writing a
  submission-shaped file of abstentions create a false artefact?
- **Q3.** For `bundles`, the thesis's banks are the voxel, the neighbourhood, the lens, the plate,
  the dome link, the ring, the conversation and how it came out. Which are honestly writable today,
  and which would be fabrication?
- **Q4.** Does task 1.4's route rename have to precede everything, or can the stages be built against
  the object model's names while `ROUTE` is corrected in parallel?
- **Q5.** What in this plan is scope that looks cheap and is not — where does "non-stupid image, even
  if not good quality" hide a week?
- **Q6.** What must the MVP refuse to do, so that building wide does not quietly assign meaning the
  founder has not given?
