## ADDED Requirements

### Requirement: Entry documents name the current architecture and change owners
The documentation SHALL route a reader to the nine-stage intended architecture and SHALL distinguish the full architecture, immediate breadth-first work and substrate refinement.

#### Scenario: A reader opens the build plan
- **WHEN** a reader follows the entry document's build link
- **THEN** the active breadth-first change is named and the older packet work is identified as substrate rather than the full route

### Requirement: Progress claims carry evidence and scope
The project SHALL distinguish dated observations from current computed state and SHALL retain incomplete engineering or domain obligations explicitly.

#### Scenario: A candidate runs and renders but has an unresolved certificate
- **WHEN** its task record is reconciled
- **THEN** implementation and run evidence are recorded while the task remains incomplete with the certificate limitation named

#### Scenario: A shell returns a construction absence
- **WHEN** its gallery contains a frame or a route entry
- **THEN** documentation distinguishes that status frame from a study-derived constructed relation

### Requirement: Planning commands expose whole task units
The planning commands SHALL default to the active breadth-first change and SHALL print a selected open task with its continuation and acceptance text intact.

#### Scenario: An open task spans multiple lines
- **WHEN** the unit command prints the next open task
- **THEN** it includes the whole checklist item through its final continuation before the next task or section
