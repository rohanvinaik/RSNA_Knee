## Frozen worker interfaces

All new modules live in knee.diagnosis. Dict/array exchange is deliberate; original values, source scope and calibration metadata remain retained. A squint profile schema knee.squint-profile/v1 has subject, banks (mapping stable bank name to three nonnegative integer counts, negative/middle/positive), and source metadata. These are exact counts of orthogonal rows; the common 512 Hadamard factor cancels in comparisons. Missing banks are absent, never measured middle. Bank names retain acquisition view, metric, direction/subregion and scale. The common quantization procedure identity is versioned; realized scan-local bounds are retained in source context, never chosen by labels or replaced by healthy-cohort bands. Counts can be represented compactly; no dense per-pixel hypervectors.

### Writer: squint_profiles.py (native writer owner)
read_study_squints(root: Path, study_uid: str, *, io_workers: int = 8, tile_mm: float = 10.0) -> dict. Returns study_uid, series list and work counters. Each series dict has series_uid, view (orientation, fluid_sensitive, fat_suppression), stack (existing SquintStack), shape, geometry/source information and cached cheap metric/code arrays. Reuse existing corpus/series reader and read_squint_stack; use bounded concurrent file reads. No anatomy reconstruction or drawing.
profile_window(series: dict, window: tuple[int,int,int,int,int,int], *, subject: str) -> dict. Window is half-open z0,z1,tile_r0,tile_r1,tile_c0,tile_c1. Stable banks write exact counts of the series' own scan-local ternary cheap readings. Preserve source window and source calibration. Same function is used by bootstrap and new-study search. Spatial/directional subregions are explicit and shared; missing geometry does not fabricate orientation.
merge_profiles(profiles, *, subject: str) -> dict adds identically named banks while retaining view/source lineage.
cosine_evidence(left: dict,right: dict) -> dict returns code, dot, left_norm_sq, right_norm_sq, common_banks; integer terms over only jointly speaking banks, no square-root decision. Empty/no-overlap is named silence. Must match existing count arithmetic.

### Bootstrap: squint_memory.py (native compiler owner)
compile_bootstrap(root: Path, products: Path, out: Path, *, selected_uids=None, io_workers=8) -> dict. Build an immutable compact memory from the 58 pre-existing products and independent train.csv calls. Resolve saved supports/frames/key views into useful coarse regions; do not redo recognition or require perfect boundaries. Every individual case has case_id, study_uid, subject, condition_calls (question -> signed digit), profile, regions, full_profile/full_source provenance, teaching source. Positive condition -> implicated object's presentation. Object with no positive condition implicating it -> normal for its applicable conditions. Keep typed condition configurations and multiple diagnoses, do not label each constituent damaged. Full and cheap descriptions remain paired; comparison requires compatible declared bank meanings and procedures, whether those banks came from full or cheap readings. A mode name alone neither permits nor forbids comparison. Do not expand millions of silent rows into JSON.
load_memory(path: Path) -> dict verifies schema and opens compact read-only cases/arrays; schema knee.squint-memory/v1. save_memory(memory: dict,path:Path) -> dict atomic immutable publication. Cases are in memory['cases']; metadata includes questions, procedure/version and source identities. Array formats must avoid pickle. Memory loaded once per operation/process with shared read-only backing where possible.

### Locator/recall: squint_locator.py (native locator owner)
locate_objects(study: dict,memory: dict,*,deadline: float|None=None) -> dict. Returns objects mapping canonical subject to status/profile/regions/evidence. Anchor bones first, dependents constrained by current-study anatomy. Stored case physical extents/proportions are priors, never another patient's coordinates. Search only useful leg tiles, reuse candidate-window counts, preserve partial views. No accepted full masks required.
prepare_recall(memory:dict) -> dict prepares fixed individual case comparisons and source-backed trust records once. A conservative finite-data nonmatching/opposing-case envelope may be computed before inference with its exact population/scope retained; label-selected banks, numerical guesses and claims of calibrated error probability are forbidden. If no justified comparison envelope exists, keep proposals rather than invent authority.
recall_object(profile:dict,memory:dict,*,question:str,exclude_study_uid:str='') -> dict returns existing-style outcome/case_terms/speaking_calls/nearest signed cases/veto and unavailable records. Every eligible case reaching its declared radius speaks; no nearest-case or majority verdict. Existing exact retrieval primitives may be reused through an adapter. Ordinary negative calls are not near-miss vetoes.

### Root-owned integration

### Claude Max-owned candidate lanes
squint_contracts.py: twelve typed domain-contract declarations plus pure combination and continuous ranking. No generic rule DSL. Necessary/sufficient/supporting/alternative presentations are distinct; normal context tissue is not a false required finding. Unmeasured != observed negative. Conflicting assignments remain conflict. Proposed approved serialization p=(3*r+1+e)/9, r=0 defeated/1 open/2 assigned, e in [0,1] from exact signed whole-case cosine evidence. No endpoints, fit or artificial tie breaks. Existing 1/0 policy remains legacy and is not production default for squint memory.
squint_reports.py: independent report-to-call input/output and admission/deduplication, exact supporting sentences, scope/negation/uncertainty; no runtime teaching or predictions as labels. Reader can author report calls in batches; ambiguous calls are retained for human review.
kaggle/squint-production/: thin private notebook/script deployment and private dry run, offline CP313 wheels, local code, four study workers, official UID order and twelve columns, no competition submission.

## Role-qualified configuration cases
Individual same-study object profiles may also be assembled into a `diagnosis/<condition>` case. Every bank is qualified by its original object role, missing roles remain explicit, and only the independent official label supplies the separate condition call. This is one observed configuration, never a class prototype. Production constructs the identical role-qualified query from already located objects and recalls it beside the object voices. No study labels enter query construction. Rohan explicitly resolved the categorical combination question: warranted whole-configuration recall may decide when no necessary anatomical finding contradicts it. Clean necessary negatives remain decisive; conflicting warranted configuration/anatomical evidence stays open. Continuous ranking and source provenance remain separate from that categorical decision.

## Full and cheap descriptions coexist

Rohan supplied the cell thesis's full/cheap profile figure again and explicitly emphasized their coexistence. A case retains its richer full description and its cheap observations of the same anatomical support under one object identity. Production does not discard the full description or manufacture its unwritten banks in a cheap query. Compare only compatible declared bank meanings and procedures; differing actual readings stay different, and an unwritten bank is not a measured middle or a normal finding. A bounded additional reading contributes its own addressed banks to that object. The complete bootstrap H5 remains available without becoming a mandatory inference prefix. A fallback location marker retains that limited meaning; it must not silently replace an available native object support when forming the paired cheap description.

The portable memory retains each exact full object record (including sparse count rows and assembly/status metadata), with shared fingerprinted layout/carrier/reference context. `full_profile_contexts` and `full_profile_payloads` hold those records once; canonical cases and condition-configuration roles link to them. Original H5 paths remain provenance, not required files for offline full-profile reading. `full_profile_from_case(memory, case, subject=...)` resolves through the same public `profiles_from_manifest` adapter as the original H5 reader. Missing full rows remain explicitly unavailable.

Memory publication verifies every distinct retained sparse payload through that reader and records the actual count. A malformed later payload blocks publication even if the first is valid or the optional prior receipt is absent. The inference loader validates identities and sparse storage without expanding full CountBundles; full readback is lazy. This storage binding does not equate incompatible full/cheap layouts or add an unconditional full-profile computation to production.
