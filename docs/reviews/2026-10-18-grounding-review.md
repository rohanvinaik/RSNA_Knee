## Remaining drift risks

### 1. Reading and loading are not an operational fidelity check

Plan §0 specifies sources and pictures; §§14–15 specify the intended transformations. It does not
by itself show that the next proposed operation follows them. The recurring error occurs after
the agent can paraphrase the thesis: it chooses a different objective. The operation and its
consumer must be checked before dispatch/integration. Hashes establish identity, not meaning.

### 2. Current and historical instructions still coexist in entry documents

NEXT's "Exact next action" marks P1 accepted, then item 2 repeats that it has NOT been accepted,
qualified by a preceding historical note. Its historical source paragraph says HEAD a118db8
"is the build", then appends a dated correction. FULL_BUILD_PLAN §2 has the same old HEAD,
and P1's procedure retains the prior not-accepted statement with a later note. These are qualified
historical statements, not proof the agent has actually scheduled old work, but they create
avoidable ambiguity in a continuation interface. Put current state in one place and make other
locations point to it; preserve old status in its source-pinned history.

HOW_TO_BUILD's "Still owed" preserves necessary obligations but also old implementation claims.
The plan correctly labels them not rechecked. A new agent should verify their current status,
not treat the historical defect description as instructions to rebuild a completed capability.

### 3. Worker context differs from the lead's context

The actual recorded cheap-worker invocation uses `--safe-mode` and disables tools/settings/MCP.
Local help explicitly says safe mode disables CLAUDE.md and hooks. Whole relevant meaning and
corrections must therefore be present in the rendered packet. Updating CLAUDE.md or a memory file
cannot repair a task already sent through that route. A text-only worker cannot view named images.

### 4. The workflow needs durable invalidation, not post-hoc disclaimers

The withdrawal fixes the known P2a attempt. The commits do not introduce a dependency-aware job
registry that prevents a result produced under superseded premises from being used after compact.
The six other packet checks were stopped and remain unaccepted, as §13 records. Their output
must not be promoted by its presence or completeness. The reusable fix is explicit dependencies,
prompt/contract revisions, named state and prompt stopping/quarantine of affected work.

### 5. The cleanup checker establishes less than an enforcement gate

`grounding-cleanup-20261018/check_kept_lines.py` checks individual line membership/substrings,
ignores order/association, and prints missing lists without setting a failing exit code. Its
docstring asks that listed differences be reviewed; it is a read-only diagnostic, not a
blocking semantic-preservation test. The human classification and complete destination review
remain necessary. Future automation should validate complete units, source freshness, explicit
supersession and required-reading reachability, and fail machine-checkable violations.

### 6. Automatic import is a configuration claim requiring runtime evidence

CLAUDE.md contains the intended imports. This review did not establish how each client or child
actually loads them, what a startup hook supplies, or whether a resumed session uses fresh text.
The source instruction itself is not a receipt of delivery. Record the actual rendered worker
input and verify client-specific startup/compact behavior separately. Do not remove primary
grounding to save context; split workers' tasks and supply their full relevant units explicitly.
