## Meaning and exact arithmetic

The anatomy's bounded relational structure constitutes the object and constrains its possible
states. It is not merely a search hint added to an otherwise unconstrained recognition problem.
Representing the actual structure eliminates proxy computation, inference and uncertainty that
would otherwise have to be paid for. The efficiency/correctness connection is foundational.

A place carries the measurements and structural information already available about it, in
separate named banks at their respective scales. A measurement knows its quantity, source and
scope. Its inferred anatomical meaning and the evidence warranting that meaning stay distinct.
An exact carrier does not make an earlier interpretation infallible.

**One anatomical object has one HDC representation across all its lenses and views.** Rohan's
explicit clarification is retained in the conversation above. Its separately resolved sagittal,
coronal and axial key views contribute to that same object's directional, scale-aware encoding.
Lens, view, direction and scale remain distinctions in the encoded facets themselves, beside their
retained source addresses and provenance. Per-observation bundles are intermediate contributions;
the completed output is the unified object profile. Writing unrelated per-view profiles or pooling
view-specific readings into an undifferentiated bank does not complete this contract.

The declaration-driven production handoff now supports a unified object composition from retained
per-place rows. Its real study consumer shares preparation, frames and arrays, publishes sparse exact
counts with original place links, and preserves unavailable facets. This establishes the composition
mechanism; the full source-backed MRI bank/reference catalogue and remaining source families are
still required before claiming the complete MRI representation. The cell-specific eight directions
and four rings are not automatically an MRI layout. Rohan explicitly directs the MRI extension to
follow from the primary theory, anatomical domain structure and the recorded conversation. Derive
and record that engineering binding rather than waiting for him to supply cell-style MRI bins.
Use the existing patient-frame geometry, anatomical axes and three-key-plane object reference;
retain source resolution and actual scale, and keep unavailable spatial facets unread. Preserve the
one-object target through every mechanical adapter task.

Each bank has 512 orthogonal Hadamard rows. A numeric metric writes one of three distinct rows
for below, at, or above its explicitly defined reference. Words have distinct rows too. The
healthy anatomical state is the intended reference for the knee's healthy profile. An unread
metric writes no row. Thus measured zero, missing reference, unavailable source, abstention and
absence are different records. Opposite deviations never cancel into normality.

For counts c and d, the vectors have dot product `512 * sum(c_i*d_i)` and squared norms
`512 * sum(c_i*c_i)`. Counts therefore implement exactly the same comparison. Bundles add,
are independent of order, and subtract exactly when the subtracted counts are present. The
bundle has an exact Hadamard decode. Count comparisons use whole integers and rational levels,
without floating-point cosine or square-root decisions. A question selects its banks before
the run; the comparison jointly reads all selected banks spoken by both sides. A silent bank
is omitted from the dot and both norms. Different carrier, layout or reference identities
are not silently compared.

## Existing producers and what the encoder consumes

| Existing information | Encoding role | Address and distinction preserved |
|---|---|---|
| Acquired signal, darkness, distance, component and other lens arrays | Per-place or explicitly scoped metric readings | Actual array key/digest, units, available mask, native slice and crop window; no re-running recognition |
| Resolved/reading supports | The places whose measurements form this observation's profile | Object, series, view, slice, artifact, support, row/label and original rule code |
| Cheap squint/local/whole-series readings | Their own declared scale/facet banks, where a producer actually measured them | Producer, resolution, scope and acquisition; coarse context is not a fine boundary |
| Cross-view correspondence and anatomical relations | Separately typed relational information for the later declared banks | Native, laid and projected provenance; authored anatomical definition versus measured relation |
| Physical frames and source windows | Exact placement of each retained reading | Native row/column plus source series/slice and patient-frame transform where retained |
| Healthy/reference statements | Explicit, sourced zero/reference contract for the named metric and acquisition | Source, units, object/lens/sequence scope, reference ID and exact comparison edges |

The profile is a bundle of places, not a replacement for them. Keep each place's row codes
and the addressed original values beside its counts. Development retains source archives. Competition
mode instead retains complete final object outputs, their measured values and necessary provenance,
as Rohan explicitly authorized in [the retention exchange](conversations/2026-10-20-competition-object-retention.md).
Active support/value addresses must resolve in that final product before consumed intermediates are released.
Per-place rows require a compact integer index per metric, not 512 dense values per bank per
pixel. Dense vectors are materialized only for a bundle when needed. Shared measurements,
array decoding and digest verification are reused within their valid source scope. Completed
study working data can be released after its encoding consumer finishes.

Three key slices constrain a reference location. They are not a reconstructed volume. Several
views can measure the same tissue; adding observation counts does not measure additional
physical tissue. Support/depth ownership must be explicit before a physical volume consumer
is built. Do not extrude a representative mask or sum overlapping acquisitions as volume.

## Knee directions, scales and the shared object profile

Rohan directs this extension to follow naturally from the thesis and the anatomical domain; the
cell's eight planar directions and fixed micrometre rings are an example, not knee constants.
The knee implementation reuses `study_map/v1`: the point constrained by the three selected key
planes, their retained precision, knee side and the measured leg scale. Native row/column points
use their own retained origin and 3×2 basis; physical trace points already use patient LPS.
No mask is extruded and no volume is inferred from several overlapping views.

The existing anatomical convention is medial, posterior, superior. Each axis is below, within or
above the reference precision interval. This interval describes the resolution of that geometric
reference, not a healthy tissue threshold. The 27 joint directional states remain distinct; the
known centre is different from an unconditioned overview. An unavailable reference, frame,
precision or side leaves the affected directional reading unread. Original coordinates and each
available axis remain retained. A known measured scale permits continuous normalized coordinates;
a missing scale is never replaced by a claimed measured value of one.

An explicit `object_composition` declaration gives its version, the ordered full three-string
`view_roles` (orientation, contrast and fat suppression), and `bank_plans` naming each base bank's
lens and actual measurement `scale_scope`. Each base bank expands into overview and directional
facets for those declared views. Direction conditioning does not change measurement scale; the
leg's normalization scale is not the scale at which a pixel lens was measured. No patient UID
enters this common layout. The canonical facet registry is fingerprinted into the actual compiled
layout before contributions are encoded; the shared carrier is built from the expanded bank names.

The study composer re-encodes retained per-place metric rows into those named facets; it never
renames an earlier pooled CountBundle. Available readings contribute to their view's overview
and, when measured, their directional facet. Source references retain their acquisition scope.
Duplicating an observation plan does not change a healthy-reference identity or create a new
measurement. An exact repeated source/place/facet/metric event counts once and keeps every link;
different observed codes for that same event remain a named conflict. An unread link is not a
contradiction of an observed reading.

Reference identity is qualified by the actual declared view. A profile applying to every view
expands that scope before references are fingerprinted or checked for conflicts. It cannot hide
a contradiction with a reference explicitly qualified to one of those views. Equivalent scoped
meanings have the same identity; a missing reference supplies no competing meaning and never
borrows another profile's reference.

The production operation reads the map pointer published by `finish_map` on the source record;
`result.study_map` itself contains only counts. It loads that already-produced map once and
retains its canonical record digest. Per-object geometry contexts and per-outcome directional
subsets are shared. The publisher interns shared coordinate/index arrays and keeps compact row
status arrays. It writes one canonical profile per object under `object_composition`, plus the
original intermediate observation profiles. Object receipt entries link directly through
`encoding_object`. The existing NPZ/XZ or H5 writer remains the single persistence path. Original
anatomical relation context remains retained. Built-in MRI also prepares an exact
`authored_definition` context bank once from the existing anatomical relation statements.
Each word preserves the full subject, predicate, ordered targets, qualifier, source and basis.
Per-object row codes, unique rows, counts and an exactly decodable carrier vector are published
under the object's definition-context link. Repeated identical authored statements count once
and retain their original links. This is a separately identified role within the object record:
it describes the authored definition, not measured relation satisfaction, a healthy numeric
profile or an additional observation vote. Measured MRI and authored-definition layouts are
explicitly distinct and cannot be silently pooled or compared as if interchangeable.

Each canonical object also receives a support-ownership account. It links actual global profile
and outcome indices to the persisted coordinate member, source artifact, target acquisition,
slice and frame. `record_series_uid`, `record_artifact`, `record_view` and `record_slice_index`
identify the record carrying the observation. `owner_*` and `artifact` identify the record owning
the measured arrays. `target_series_uid` comes only from the observation's explicit acquisition.
A `target_artifact` links a provided record in that acquisition, with its own root and named
availability status; it never asserts that record's main plane is the observation's native plane.
No matching provided record means unavailable, and a missing observation UID remains unknown.
Original off-slice addresses take precedence over a bootstrap record's slice.
Duplicate descriptive support links preserve all provenance; incompatible descriptions remain
named conflicts. An unaddressed or unavailable outcome remains named. This account does not
construct volume: overlap between acquisitions and physical support depth remain unresolved
unless a producer actually supplies the corresponding evidence.

## Normal references from medical sources

Rohan authorized open medical reference texts as a source when the normal profiles are not
already local. Begin with the medical source records in OBJECTS_AND_CONDITIONS and the actual
resolved definitions. Add source-backed normal morphology, relationships, continuity and
sequence-conditioned appearance to the metric's contract. Keep its source and qualifications.

For example, normal meniscus has a low-signal triangular cross-section, with different expected
medial/lateral horn morphology and specific attachments. Those are several separable readings,
not a single brightness number. [Lefevre et al., normal MRI of the meniscus §5.3](https://pmc.ncbi.nlm.nih.gov/articles/PMC4766355/).
Normal appearance also depends on the acquisition: routine knee protocols use several planes
and contrasts, with institution-dependent scanners and sequences.
[Chien et al., technical considerations and normal meniscal anatomy](https://www.polradiol.com/pdf-125659-108819?filename=Magnetic-resonance-imagin.pdf).

An ordinal clinical statement is not a universal raw MRI pixel value. Implement it through
the explicitly named measurement or relation it describes. A calibration read from the scan
and a healthy anatomical profile each keep their own role; a whole-bone intensity median is
not automatically a healthy marrow-only profile. Do not manufacture numeric normal limits
from a study's percentiles, test-fixture edges, labels or desired recognition outcome.

Each MRI reference row needs: object; acquisition/lens; quantity and units; normal statement;
source and coherent source section; actual producer; measurement-to-reference interpretation;
supported numeric bounds or declared words; and any unavailable/qualified case. If the source
does not supply a number, keep that fact and encode the available qualitative/relational
reading through its appropriate producer. Do not make an unsupported numerical substitute.

## Production interface and bounded implementation

`knee.encoding.counts` owns exact count addition, subtraction and joint-bank comparison.
`carrier` owns the seeded 512-row basis, exact encode/decode and actual-permutation identity.
The production carrier evaluates that same Sylvester matrix through nine exact butterfly stages,
rather than dense matrix multiplication. Its dense basis remains the comparison reference; no
row, identity, count or overflow contract changes. Carrier identity is immutable and fingerprinted
once per prepared carrier. This reduces repeated arithmetic and preparation without approximation.
`places` owns declarative bank/metric row assignment, supplied references, per-place row codes
and named decode. It contains no default MRI profile. `handoff` reads addressed retained arrays;
`operation` is the per-study consumer wired into the existing production command when an
explicit encoding specification is provided.

The declaration contains a version, ordered banks/metrics, and profiles selecting an object,
provenance, kind, support and optional view. Each profile explicitly binds every declared metric
to an existing value array and availability array, plus a crop-window array when needed, or to
an explicit unread source with a reason. Numeric
references name their source, units, identity and finite low/high edges. An absent reference is
named `missing_reference` and writes no digit; valid other readings and original values remain.
Layout identity includes ordered meanings; reference identity includes the exact supplied
reference set. Renaming a version alone cannot conceal changed row meanings or zeros.

The ordinary adapter supports native/laid single-plane boolean or labelled support and row-addressed
mask stacks, including cropped measurement arrays. A projected target stays `target_only`.
The explicit fibula axial packed family validates its owning artifact separately from its target
acquisition and checks retained row/slice/frame evidence. Its observation count is target pixels;
its region support has a separate count, and neither is substituted for the other. Posterior traces
resolve the target observation and its source artifact owner separately, retaining original LPS
points with per-point light/flank readings. They are not rasterized. The joint axial sampled-profile adapter also preserves its sparse native sample coordinates and
white-sample count (which differs from the number of addressed samples), with shared context and
unread bindings. Native slice profiles use actual series/slice indices, producer status
words and retained area values; they supply no representative pixel. Coarse blocks use
their true grid coordinates, native window, block size and physical measurement scale.
Their unfiltered and scale-filtered readings occupy separate banks; neither is a fine
cortex boundary. A holder's fibula coarse rows resolve their target through the actual
`fibula_key_planes` record, keeping owner and target acquisitions distinct. An unsupported
address returns `support_adapter_required` or `plane_address_required`, not a fabricated mask.
These remaining adapters are implementation work, not evidence those anatomical objects do
not exist. New slice records retain the frame already computed by recognition; an older record
without that frame cannot claim it was retained.

Retained recognition sources remain lossless NPZ/XZ plus JSON/XZ. Encoding output defaults to
that container pair; an explicit `storage: "h5"` selects one H5 product containing the same
manifest and numeric arrays, without duplicate sidecars. Install the optional `hdc` extra for
production H5 use; the development group includes h5py so the ordinary CI suite exercises it.
`open_product` reads either product and verifies each requested array once against its saved
dtype, shape and digest, shares the read-only result, then releases its cache on close. New output
addresses are absolute. A relative legacy archive reference is resolved only from its manifest
folder; older cwd-relative experimental products need explicit repair, never a guessed fallback.
This implements storage and exact readback, not final spatial/depth ownership or representation
sufficiency. Development retains original measurement values in their addressed recognition artifacts. Competition
mode must publish all necessary object support/value arrays in the final product and verify them with
the public reader before releasing this run's consumed intermediate files. Original source references
remain provenance, not active dependencies on deleted archives. Missing required dependencies or failed
publication/readback prevent cleanup. Changing a container never authorizes precision reduction.

H5 datasets use standard lossless gzip level 4 with shuffle for nonempty, nonscalar arrays;
scalars and empty arrays remain unfiltered. The public reader also accepts earlier uncompressed
products. Dtype strings, shapes and exact decoded bytes, including signed zero and NaN payloads,
remain the contract. Storage measurements belong to their source-pinned proof; compression of
one development encoding product does not establish the full competition storage envelope.
Schema v2 additionally shares byte-identical arrays through HDF5 hard links and preserves
every public array name in an ordered key table. Identity includes actual dtype, shape
and bytes, with exact comparison after hashing. Its manifest and name table use declared
lossless gzip. The reader accepts legacy v1 products and refuses unknown or inconsistent
schemas. Sharing container storage never supplies another measurement vote.

Built-in MRI selects schema v5 through `h5_encoding: "modular_hybrid"`. For each unique
nonempty array the writer selects the shortest exact payload: original bytes, row-predicted
bytewise XOR, or unsigned modular row differences. The modular transform interprets each raw
item's bits as a little-endian unsigned word, never as floating arithmetic; cumulative modular
addition reverses it exactly. Unsupported word widths retain the earlier transform or raw bytes.
Byte planes are shuffled and losslessly XZ-compressed. This extra compression has a measured
writer CPU cost; source-pinned whole-operation resource acceptance remains required.

Descriptors retain original dtype/shape, predictor stride, payload span and canonical alias.
Empty arrays keep individual zero-length entries. No rounding or precision change occurs.
Requested arrays are decoded lazily by span; the decoder checks complete streams, exact output
length and a 256 MiB dictionary-memory ceiling. Shapes must have representable NumPy rank,
dimensions, strides and byte size even when they contain zero elements. The public product
reader preserves digest verification and normalizes lazy storage failures to its named errors.

Explicit declarations select `h5_encoding: "legacy"`, `"compact"`, `"byte_xor"` (v4), or
`"modular_hybrid"` (v5). Older declarations retain their previous writer default;
`h5_compact: true` continues to select v3 and conflicts with a different explicit H5 encoding.
A declaration using NPZ/XZ does not apply its inactive H5 codec. Schemas v1–v4 remain readable.
All versions keep the same public array names, dtype, shape and exact decoded bytes. The
production route has focused exactness and refusal checks; integrated workload measurements
and the full competition storage/compute envelope remain separate acceptance obligations.

## Running the explicit handoff

The existing production command accepts `--encoding-spec <declaration.json>` and
`--encoding-run <output-directory>`. It prepares an owned immutable declaration once before
opening studies, reuses its layout/carrier/reference identities, and runs the addressed encoding
consumer before either immediate receipt publication or no-draw batch staging. Object entries
link to the resulting per-study manifest; the manifest keeps measured encoding work counters.
Arrays are opened and verified once per source artifact, shared by its object consumers, and
released before the next artifact. Reading an existing persisted product is not a new recognition
pass. A later in-memory handoff may remove that I/O while preserving the same contract.

Alternatively, `--encode-objects --encoding-run <output-directory>` installs the built-in
retained MRI declaration through that same preparation and publication path. It covers
the canonical object catalogue, ordinary addressed masks, native slice profiles, coarse
blocks, packed fibula regions, all five posterior trace objects and sampled joint readings.
It uses one common carrier/layout and retains unsupported observations as named outcomes.
Generated ordinary profiles reuse the prepared layout; they bind every added metric as
measured or explicitly unread. A native mask's own frame remains with its observation in
the public object output. Off-slice masks cannot borrow middle-slice B1 measurements.
This installed measurement declaration supplies no invented clinical reference ranges.

Boolean lens arrays can write the declared words `False` and `True` directly. A measured false
value writes a real row; an unavailable value writes none. This requires no invented numeric
healthy threshold and does not label either boolean as healthy by itself. Source-backed words
and structural relationships can be encoded while genuinely unspecified numeric references
remain named. Missing raw-intensity limits must not halt the useful structural representation.

Each metric's compact row codes and native places remain reconstructible beside the exact
count table and bundle vector. Counters report actual artifact opens, verified arrays/bytes,
addressed places, emitted arrays/bytes and bundles. They do not claim full-competition capacity
or that a partial MRI bank catalogue is sufficient for every later question.

## Context and source-family contracts

An ordinary or posterior-trace profile may explicitly bind a scalar with `source: "record_context"`, a path of
mapping keys/list indices and scope `acquisition` or `record_plane`. No expressions are evaluated.
Each place inherits the reading at its scope, as in paper §7.1: the scalar is read once and
broadcast as a shared view into the single place-encoding pass. Missing, null and nonfinite
sources remain explicitly unavailable; the source path, scope, actual value and address are kept.
A plane context cannot migrate to another slice. A trace reads its actual target record; its
artifact owner can be a different acquisition. Its context address retains both identities and
the actual trace slice. Acquisition scope can apply across that acquisition's slices; plane scope
requires the target record's slice to match the trace row. Both adapters use one scalar reader,
including unavailable values, so path/type/availability semantics do not diverge. Live tuple views
and serialized list views have the same identity when their ordered values agree.
Packed context still requires resolution of its own target record and is currently refused rather
than borrowing an artifact owner's context.

Every supported address family accepts `source: "unread"` with a nonempty `reason` for an
inapplicable or unmeasured facet. It cannot also name an array, context path or availability
source. The declaration still binds every metric, so native planes, packed regions and physical
traces can share one layout without fabricated observations. Unread values and availability use
shared read-only scalar views; they write no row and need no numeric reference. An observed
numeric reading without its required reference instead remains `missing_reference`. These are
different retained states, never a measured middle row or evidence of anatomical absence.

The posterior trace producer retains per-row slices and start/stop codes, but no second per-row
target UID array. Its row-to-target provenance is the target record’s Observation plus the source
artifact and row address. The adapter validates that retained lineage and does not claim an
independent UID cross-check absent from the source. A nearest traced slice can differ from the
record’s bootstrap middle slice; its retained row slice is the actual address.

The factual normal-reference catalogue and producer correction are retained under
`data/readings/hdc-20261020/source-inventory/`. They index 42 canonical labels and the marrow
field; they are not an installed MRI bank layout or healthy numerical profile. `describe_objects`
summarizes existing observation rows. Measurement and family producers create the underlying
values and supports. Source statements, measured relation satisfaction and anatomical naming
inferences retain their own provenance.

## Efficiency at the later AI boundary

Rohan's 2026-10-20 direction makes the complete recognition/encoding/AI/diagnostic operation the
efficiency scope. Thesis §7 writes the representation from measurements already available; §§13.1–13.2
make sparse counts and carrier vectors exact equivalent forms for comparison, with unspoken/unselected
banks excluded from arithmetic. Keep each object's combined view/lens/direction/scale profile and
place/value lineage reusable. Future consumers must not need a new recognition pass or repeated
bundling, and a count-only operation need not materialize dense per-pixel vectors. File compression
is assessed with writer cost, relevant downstream reads and retained information in the same account.

Current `encode_study` owns live emitted arrays and the composed result before the common writer;
its public return supplies saved-product metadata, not a specified AI implementation. Preserve that
lifetime as the integration seam so a later consumer can read the actual exact representation before
compression/release, without a forced disk round trip. H5 remains the durable pre-AI output/teaching
interface under the current retention contract. The approved decision, teaching, query-bank and
ranking mechanisms are in AI_DIAGNOSTIC_DESIGN.md and SQUINT_PRODUCTION_CONTRACT.md. Do not transplant the cell instance's AI policies,
temporal dynamics, thresholds or normalization as MRI defaults.

Competition scheduling must cover the entire study operation. Independent study workers perform
recognition, exact encoding and one complete readback using worker-local invariant preparation. The
coordinator consumes compact verified metadata, validates study/configuration/product identities,
stages the aggregate receipt and releases owned intermediates. Array payloads do not travel through
IPC, and encoding/readback are not repeated in the coordinator. This is synchronous bounded study
parallelism; source images, mutable state and later inference state remain scoped to that study.
The live packet distinguishes this binding construction contract from verified implementation.
