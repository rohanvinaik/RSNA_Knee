in this workshop. The founder's shared-knee relation is the premise; acquired
slab support limits coordinate use, not object identity.

`run_study` reads the study once, calls each original measurement once, then
`converse` over those returned records. `AnalysisRequest.conversation=True`
explicitly enables this capability. The writer serializes returned records;
Hamilton observes them; the renderer draws saved arrays. None is an alternative
segmentation algorithm.

Every ordered same-orientation pair participates. Original bounded B1 bands are
transported and the recipient's unchanged pixels read with its own split. A
donor can select one bounded native run despite other nonmatching runs. Missing,
open, multiple, disjoint, out-of-slab and donor-only readings remain distinct.
Derived intersections never become donors in this pass. Their widths are sample
envelopes, not cortical thickness or precision claims; coarser resolution metadata
is retained.

Concurrent and conditional connectivity are separate returned maps. The latter
also uses donor-only constraints. All original labels, every resulting piece,
original-parent identities and barrier cells remain available. OR combines
geometry, never votes or anatomical ownership. Generic chain closure and
constrained shortening remain OpenSpec task 3.8.

## Reproduce and verify

Canonical run: `data/measurements/object-conversation-b2-v1/`.
Its instrument settings equal B1: 3 mm squint/prominence, −3…3 mm profiles in
0.5 mm steps, strict JIT backend, middle acquired plane per series. These settings
were declared before the corpus run and were not selected against diagnoses.

```sh
just analyze-objects --tile-mm 3 --span-mm 3 --samples 13 --axis superior --backend jit --prominence-mm 3 --conversation --out data/measurements/object-conversation-b2-next
just same-interiors data/measurements/object-conversation-b2-v1
just same-conversation data/measurements/object-conversation-b2-v1
just interiors-status data/measurements/object-conversation-b2-v1
just conversation-status data/measurements/object-conversation-b2-v1
just conversation-picture-status data/pictures/object-toolkit/conversation-b2
just plan-check
```

Read the whole status records and their checks. B2 SAME compares every B2 array
and scalar metadata against saved/reference/JIT readings in one environment;
only reference-versus-JIT backend names differ intentionally. Saved metadata must
match its requested backend exactly. Source, writer, serializer, verifier,
environment, receipt and artifact links all participate in current standing.
Each study has an atomic checkpoint, including failed/partial states if present.
Interrupted runs are rerun into fresh directories, never silently merged.
`verification-index.json` binds the evidence files, production source and intent
tests at this checkpoint. It is a snapshot, not a substitute for recomputing
the status commands after a change.

`measurement-summary.json` computes original territories, both subdivisions,
exchange codes, sample work, raster visits and returned bytes. Counts of pieces
are geometric readings, not counts of bones or findings.

## Compute evidence and qualifications

`full-production.prof` and `call-profile-summary.json` record cProfile over the
complete production writer invocation. `production-allocations.bin/json` record
Memray's native allocation tracing over one five-series study using that same
entry point; its companion receipt is in `object-conversation-b2-memory-v1`.
Allocation totals and tracked peak are not RSS. Neither profile is a paired
speed comparison. `graph.execution.json` records actual Hamilton execution.

four-connected pieces, and strict Numba twins execute repeated sampling/raster
loops. The raster reference retains inclusive ties and clipping, int32 label
limits and int64 visit bounds. The measured B2 cost does not warrant a new native
C/Rust layer in this increment. Linux/Kaggle remains a separate deployment proof.
